# Edge AI Based Smart Electric Vehicle Charging Station Optimizer

Embedded firmware for an ESP32-based smart EV charging station bay optimizer.
This repository contains three independent PlatformIO projects — **BAY 1**,
**BAY 2**, and **BAY 3** — each implementing the same optimizer logic for one
physical charging bay.

## Overview

Each bay runs on an ESP32 (DOIT DevKit V1) using the Arduino framework. The
firmware:

- Reads bay sensors: voltage (ADC), current (ADC), DHT22 temperature/humidity,
  and plug-in/plug-out button states.
- Runs an on-device (edge) optimization routine that predicts EV arrival
  probability and session duration, then decides load and relay behavior.
- Publishes telemetry to ThingsBoard over MQTT every 5 seconds.
- Supports remote configuration through ThingsBoard shared attributes and RPC.

## Technologies Used

- **ESP32** (DOIT DevKit V1) — target board, configured in each `platformio.ini`.
- **Arduino framework** — `framework = arduino` in `platformio.ini`.
- **MQTT** — `PubSubClient` library; telemetry and RPC are exchanged with the
  broker defined in `src/config.cpp` (`MQTT_SERVER`, `MQTT_PORT`).
- **ThingsBoard** — the MQTT broker host is `mqtt.thingsboard.cloud`; the
  firmware uses a device access token (`TB_TOKEN`) and supports shared
  attributes (`attributes.cpp`) and RPC (`rpc.cpp`).
- **Wokwi simulation** — each bay has `test/diagram.json` and `test/wokwi.toml`
  for simulating the circuit and flashing the built firmware.
- **Edge AI** — `src/edge_ai.cpp` runs on-device inference using models in
  `src/model.h` (a logistic regression for arrival probability and a decision
  tree for session duration, auto-generated by `train_models.py`).
- **Additional libraries** — `DHT sensor library`, `Adafruit Unified Sensor`,
  `ArduinoJson`.

## Getting Started

1. Install PlatformIO (VS Code extension or CLI).
2. Clone this repository.
3. For each bay you want to use, copy `BAY N/examples/config.cpp` (or create
   `BAY N/src/config.cpp`) and fill in your Wi-Fi SSID/password and ThingsBoard
   device access token. `src/config.cpp` is intentionally git-ignored so real
   credentials are never committed.
4. Build and upload a bay:

   ```
   cd "BAY 1"
   pio run -t upload
   ```

   Repeat for BAY 2 and BAY 3 as needed.

## Configuration

Wi-Fi and ThingsBoard credentials are defined in `src/config.cpp` (declared in
`include/config.h`). Do **not** commit real credentials. Use the provided
`examples/config.cpp` template and keep `src/config.cpp` local.

## Simulation

Wokwi project files are under `test/`. Open `test/diagram.json` in Wokwi after
building the firmware; `test/wokwi.toml` references the built binary at
`.pio/build/esp32doit-devkit-v1/`.

## Security

- `src/config.cpp` is git-ignored. Rotate any token previously committed.
- Never publish device access tokens or Wi-Fi passwords.
